# Свадебное приглашение-газета — дизайн-документ

**Дата:** 2026-09-09
**Статус:** согласован, готов к планированию реализации
**Публикация:** https://xeoza.github.io/ (корень репозитория `xeoza/xeoza.github.io`, ветка `master`)

## Цель

Статический сайт-приглашение на свадьбу Данилы и Анастасии 9 октября 2026 года,
оформленный как выпуск старой газеты. Гость получает ссылку в мессенджере,
открывает её с телефона, узнаёт когда и куда приходить, что надеть, чего нельзя,
и подтверждает присутствие в личном сообщении жениху или невесте.

Референс — сайт, собранный в конструкторе wedwed.ru; скриншоты лежат в
`screnshots/`. Стили конструктора не копируются: они завязаны на его рантайм и
на шрифты под его лицензией. Вёрстка пишется с нуля по мотивам скриншотов на
бесплатных шрифтах Google Fonts.

## Ограничения

- GitHub Pages: только статика, серверного кода нет, данные хранить негде.
- Node.js на машине разработки не установлен — сборка и запуск тестов через npm
  недоступны. Отсюда: никакого билд-шага, тесты запускаются в браузере.
- Основной сценарий — открытие с телефона по ссылке из Telegram или WhatsApp.

## Архитектурные решения

| Решение | Выбор | Причина |
|---|---|---|
| Структура | Один `index.html` со всем текстом в разметке | Нет сборки, нет зависимостей; страница работает при отключённом JS; корректное превью в мессенджерах |
| RSVP | Кнопки-ссылки на личные чаты Telegram | Статический хостинг не может принимать данные; внешние сервисы (Formspree, Google Forms) добавляют зависимость и уводят гостя с сайта |
| Судьба COCOMO | Удалить `index.html`, `index.js`, `cocomo2.js` | Приглашение занимает корень user-site. Файлы остаются в истории git |
| Данные | Прямо в разметке, без `content.js` | Правок будет мало; отдельный слой данных ломает работу без JS и превью ссылок |

## Файловая структура

```
index.html          вся разметка и весь текст
styles.css          оформление
countdown.js        обратный отсчёт (единственный скрипт)
tests.html          браузерные тесты чистых функций отсчёта
assets/
  cover.jpg         960×1280   пара, сердечко руками (ч/б)
  outro.jpg         960×1280   пара, в шляпе (ч/б)
  venue.jpg         1240×620   фасад дома Пушкина, стрелка «ВХОД» впечатана
  og-preview.jpg    1200×630   превью ссылки для мессенджеров
.nojekyll           отключает обработку Jekyll на Pages
.gitignore          .DS_Store, .superpowers/
docs/superpowers/specs/   этот документ
```

**Удаляются:** `index.js`, `cocomo2.js`, прежний `index.html` — они отслеживаются
git, удаление обратимо.

**Не удаляются, а вносятся в `.gitignore`:** `screnshots/` (52 МБ референсов) и
`photos/` (оригиналы снимков). Обе папки никогда не коммитились и в истории git
их нет — удаление было бы безвозвратным. GitHub Pages публикует только
закоммиченное, поэтому `.gitignore` достигает цели без потерь.

**Исходники фотографий** лежат в `photos/` с кириллическими именами и пробелами.
Переименовываются в латиницу при переносе в `assets/`: такие имена дают в URL
последовательности вида `%D0%9F%D1%83…` — хрупко и нечитаемо.

| Исходник | Назначение | Обработка |
|---|---|---|
| `photo_2026-09-09 11.42.30.jpeg` | `assets/cover.jpg` | без изменений (76 КБ) |
| `photo_2026-09-09 11.42.37.jpeg` | `assets/outro.jpg` | без изменений (96 КБ) |
| `Пушкина.jpg copy.jpg` | `assets/venue.jpg` | `sips -Z 1240 -s formatOptions 62` → ≈ 285 КБ |
| `Пушкина.jpg.webp` | не используется | см. «WebP не применяется» ниже |

**WebP не применяется.** `sips` на этой машине собран без записи webp
(`Can't write format: org.webmproject.webp`), `cwebp` не установлен. Но решающее
даже не это: готовый `Пушкина.jpg.webp` весит 344 КБ против 285 КБ у JPEG того же
разрешения — то есть «оптимизированный» формат здесь в 1.2 раза тяжелее. Элемент
`<picture>` отдавал бы современным браузерам файл крупнее запасного, что прямо
вредно. Используется обычный `<img src="assets/venue.jpg">`.

**Про порог веса.** Изначально в спеке стояло ≤ 200 КБ при 1600×800 — недостижимо:
кодировщик `sips` даже на качестве 55 в полном разрешении даёт 477 КБ. Снимок
показывается в колонке шириной 620 px, на экране с двойной плотностью это 1240 px,
поэтому исходник уменьшается до 1240×620 — там качество 62 укладывается в 285 КБ
при полной чёткости на телефоне.

Папка `photos/` после переноса остаётся на месте и вносится в `.gitignore`.
Оригиналы не коммитились ни разу, восстанавливать их было бы неоткуда, а
`assets/venue.jpg` — уже пережатая копия, не замена исходнику.

Портретные фото уже чёрно-белые, студийные, с рваной плёночной рамкой —
обработка не требуется. Фото площадки остаётся цветным: оно утилитарное,
показывает гостю реальную дверь.

## Дизайн-система

### Палитра

| Токен | Значение | Применение |
|---|---|---|
| `--paper` | `#e9e7e2` | фон светлых секций |
| `--paper-alt` | `#dcd9d3` | фон чередующихся секций |
| `--ink` | `#111` | заголовки, линейки |
| `--ink-soft` | `#3a3a3a` | основной текст |
| `--wine` | `#6e1417` | кнопки, сердечко в календаре |
| `--night` | `#1a1917` | фон блока с таймером |

Контраст белого текста на `--wine` ≈ 9:1 — WCAG AA проходит с запасом.

Бумажная текстура — инлайновый SVG-фильтр `feTurbulence` в `background-image`,
без дополнительных сетевых запросов.

### Типографика

Один запрос к Google Fonts, `display=swap`, подмножества `cyrillic` + `latin`.

| Гарнитура | Роль |
|---|---|
| Playfair Display | мастхед, заголовки секций, крупные строки, кнопки |
| Old Standard TT | надзаголовки капсом с разрядкой |
| PT Serif | основной текст, списки, тайминг |

Выбор мастхеда сделан из пяти вариантов, показанных в браузере: Ruslan Display,
Triodion, Monomakh, Pochaevsk, Playfair Display. Выбран Playfair Display —
славянская стилизация признана избыточной для свадьбы.

Oranienbaum, изначально предполагавшийся для крупных строк, исключён: он и
Playfair — обе дидоны с высоким контрастом, две однохарактерные антиквы рядом
не нужны.

### Ритм и сетка

- Mobile-first. Колонка `max-width: 620px`, на десктопе та же колонка по центру
  с более широкими полями. Не более двух брейкпоинтов.
- Чередование `--paper` / `--paper-alt` по секциям.
- Парная линейка 3 px + 1 px под заголовками — как в референсе.

## Обратный отсчёт

Единственный скрипт на сайте, ориентировочно 40 строк. Логика разделена на
чистые функции (расчёт остатка, склонение числительных) и тонкий слой обновления
DOM — чистые функции покрываются тестами.

**Целевой момент:** `2026-10-09T15:00:00+03:00`. Смещение МСК указывается явно:
без него гость в другом часовом поясе увидит неверный отсчёт.

**Склонение русских числительных.** Подписи согласуются с числом: «1 день /
2 дня / 5 дней», «1 час / 2 часа / 5 часов», «21 минута / 25 минут». Числа
11–14 — исключение и всегда берут форму множественного числа («11 дней»,
а не «11 день»). В референсе на скриншоте видно «01 Часа» — эта ошибка не
воспроизводится.

**После свадьбы.** Сайт остаётся опубликованным, и с 9 октября 2026, 15:00 по МСК
отсчёт уходит в отрицательные значения. Вместо цифр блок показывает:
«Мы поженились! Спасибо, что были с нами».

**Работа без JS.** В разметке статически лежит строка «9 октября 2026, 15:00»;
скрипт заменяет её на цифры при загрузке. Если JS отключён или не загрузился,
гость видит дату, а не пустой блок.

**Частота обновления:** раз в секунду через `setInterval`.

## Превью ссылки в мессенджерах

Ссылку рассылают в Telegram и WhatsApp, поэтому Open Graph-разметка обязательна:

- `og:title` — «Данила & Анастасия · 9 октября 2026»
- `og:description` — краткий текст приглашения
- `og:image` — `assets/og-preview.jpg`, 1200×630, свёрстанный как фрагмент
  газеты: мастхед, имена, дата, фото
- `og:url`, `og:type`, `twitter:card`

Без этого в мессенджере развернётся голый заголовок вместо открытки.

## Доступность

- `lang="ru"` на `<html>`
- Осмысленные `alt` у всех трёх фотографий
- Кнопки — настоящие `<a>`, доступные с клавиатуры и из скринридера
- `aria-live="off"` на таймере, иначе скринридер зачитывает секунды вслух
- `prefers-reduced-motion` отключает плавное появление секций
- Контраст всех текстовых пар проходит WCAG AA

## Тестирование

Node.js недоступен, поэтому тесты живут в браузере. `tests.html` подключает
`countdown.js`, прогоняет проверки и печатает зелёный/красный список.

**Автоматические проверки** (чистые функции):

- склонение числительных на граничных значениях: 1, 2, 5, 11, 12, 14, 21, 22,
  25, 101, 111
- расчёт остатка: за сутки до, за час до, за минуту до, ровно в целевой момент,
  через минуту после
- разбор целевой даты со смещением `+03:00` даёт одинаковый результат независимо
  от часового пояса браузера

**Ручные проверки:**

- вёрстка на ширинах 320, 390, 768, 1440 px
- страница с отключённым JavaScript
- поведение таймера при системной дате после 9 октября 2026
- превью ссылки в Telegram
- переход по всем четырём ссылкам: Яндекс.Карты, `tel:`, два чата Telegram

## Публикация

GitHub Pages, ветка `master`, каталог `/` (root). Файл `.nojekyll` отключает
обработку Jekyll.

Коммит и push выполняются только по явному разрешению заказчика. От заказчика
требуется однократно проверить Settings → Pages: источник должен быть
`Deploy from a branch` → `master` → `/ (root)`.

## Известные пробелы

Работу не блокируют, заполняются позже одной правкой:

1. **Ресторан** — не выбран. Название, адрес и время начала ужина неизвестны.
   Отдельный блок про ресторан не делается; в тайминге строка «Ужин в ресторане»
   стоит с прочерком вместо времени. Когда ресторан определится — добавляется
   блок между «Тайминг» и «Дресс-код».
2. **Принадлежность телефона** +7 933 277-42-29 подписана как контакт Данилы —
   допущение, подлежит подтверждению.
3. **Год дедлайна** заказчик назвал как «16.09». Читается как 16 сентября
   2026 года — подтверждение присутствия обязано предшествовать свадьбе
   9 октября 2026.

## Что решено не делать

- Не копировать CSS с wedwed.ru — чужой рантайм и лицензионные шрифты.
- Не подключать генератор статики (Jekyll, 11ty) — для одной страницы это лишние
  сущности и лишние точки отказа.
- Не выносить тексты в `content.js` — ломает работу без JS и превью ссылок.
- Не делать форму RSVP на сайте — требует внешнего сервиса, регистрации и
  упирается в лимиты бесплатных тарифов.
- Не искать в интернете фото торта под таймер — авторские права и чужая эстетика.
- Не добавлять карту-картинку в блок площадки — фото со стрелкой и кнопка
  «Как добраться» закрывают задачу.
